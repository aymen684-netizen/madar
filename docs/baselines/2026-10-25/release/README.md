## التغيير

أصبح `npm run build` ينتج حزمة مستقلة في `build/release/` تضم الأصول المبصومة وWorker مجهزًا
وخريطة المراجع وإيصالًا يغطي الملفات ومدخلات البناء وcommit المراجعة. تُبنى مرة واحدة في CI؛
تستخدم وظائف المتصفح والأداء والانتقال من الذاكرة وفحص HTTP الأثر نفسه بمعرّفه دون إعادة البناء.
يُفحص الإيصال قبل الاختبارات وبعدها. تُنسخ بيانات اختبارات Node المولدة فقط إلى `public/`.

تفشل المطابقة عند تعديل ملف أو إضافته أو حذفه، أو عند اختلاف commit أو مدخلات المصدر.
بعد نجاح جميع مجموعات المراجعة، ينشئ `release-ready` سجلًا يربط الحزمة بتشغيل CI ويصدر `reviewed-release`.
تستخدم Pages هذه الحزمة بعد البوابة؛ التشغيل اليدوي يستدعي البوابة نفسها على main.
حزم طلبات الدمج تظل للمراجعة؛ لا يجيز سجلها نشر الإنتاج.

يشير Wrangler إلى Worker المجهز والأصول المجمدة، ويمنع خطاف النشر البناء المحلي غير المراجع.
يتحقق `npm run deploy` من سجل main، وبصمة الإيصال، ومدخلات المصدر، ونجاح تشغيل GitHub للمصدر نفسه.
لا يعيد تجميع Worker عند النشر. يلزم تنزيل أثر CI المراجع مع نسخة المصدر المطابقة قبل تشغيله.
تبقى إعدادات الحساب والاستضافة الفعلية دون تغيير في هذا الطلب؛ لا توجد عملية نشر أو دمج ضمنه.

## التخزين والتحقق

تستخدم استجابات الأصول في Cloudflare `public, max-age=0, must-revalidate` عبر `_headers`.
لا تُستخدم `immutable` مع عناوين الاستعلام التي لا تحتفظ بملفات الإصدارات السابقة.
تفحص وظيفة `release-http` الاستجابات الفعلية لـWrangler للأصول وWorker: مطابقة البايتات،
الحماية والتخزين، وHEAD وETag/304 وبقاء مسارات API المحمية.
تسجل أيضًا ترويسات الاستضافتين الحاليتين بطلبات HEAD عامة في `hosting-headers.json`؛
لا تقارن نسخة الإنتاج القديمة ببايتات طلب دمج لم يُنشر.

نجحت الفحوص المحلية العامة والتنسيق والتدقيق، بما فيها رفض الحزمة المعدلة والمصدر المتغير
والمراجعة المفقودة أو الفاشلة أو التي تخص فرعًا أو commit آخر.
تعذر خادم Wrangler محليًا بسبب `uv_interface_addresses` في البيئة؛ نتائج HTTP والمتصفح وCI النهائية
وروابطها تُثبت في وصف طلب الدمج. الأرقام والبصمات المحلية في [verification.json](verification.json).

ترويسات GitHub Pages تُرصد كما ترسلها الاستضافة؛ وجود `_headers` في الحزمة لا يعني تطبيقها هناك.
قبل تفعيل النشر الفعلي تُراجع نتيجة الرصد وإعدادات الحصول على الحزمة المراجعة في Cloudflare.
للتراجع تُستخدم حزمة main ناجحة سابقة مع مصدرها المطابق، دون إعادة بناء بايتاتها.
