## التغيير المقترح وترتيبه

1. تأكيد نجاح فحوص رأس طلب الدمج الجامع، ومطابقة شجرته للنسخة التي روجعت محليًا، وقابلية دمجه
   في رأس `main` أعلاه. يحافظ دمج GitHub العادي على تاريخ #81–#85.
2. بعد اعتماد التفعيل، تحديث حقلي `production_settings.build_command` و
   `production_settings.deploy_command` في إعداد Worker Builds فقط إلى:

   ```json
   {
     "production_settings": {
       "build_command": "node scripts/fetch-reviewed-release.mjs",
       "deploy_command": "npm run deploy"
     }
   }
   ```

3. إعادة قراءة الإعدادات للتأكد، ثم دمج الطلب الجامع. يتيح هذا الترتيب وجود المستورد في commit
   الجديد الذي يطلق البناء. تبقى النسخة الحالية متاحة حتى نجاح نشر بديل.
4. تنشئ مراجعة `main` حزمة واحدة وتختبرها. بعد نجاح الفحوص، تنشر Pages الأصول نفسها، ثم ينشر
   `distribute` أرشيف GitHub Release وبصمته. الصيغة هي
   `madar-<sourceSha>-<runId>-<attempt>`؛ حزم PR غير مؤهلة للنشر.
5. ينتظر Cloudflare أحدث مراجعة مطابقة لـ`WORKERS_CI_COMMIT_SHA` على `main`، وينزّل الأرشيف
   العام ويفحص SHA-256 والإيصال والمدخلات وسجل المراجعة. ينتظر حتى 18 دقيقة، ويوقف البناء
   عند الفشل أو انتهاء المهلة. لا يعيد تجهيز الأصول أو تجميع Worker.
6. ينفذ `npm run deploy` تحققًا مستقلًا قبل الرفع. إذا تجاوزت المراجعة مهلة Cloudflare، يعاد
   تشغيل بناء commit نفسه بعد نجاحها؛ لا يُستبدل أمر المستورد بأمر بناء المصدر لتجاوز البوابة.

## أدلة النجاح المطلوبة

- نجاح جميع وظائف المراجعة على commit النهائي لـ`main`، ثم `pages` و`distribute`؛ ليست نتيجة
  PR بديلًا عن مراجعة commit الدمج النهائي.
- وجود الأرشيف والبصمة تحت tag التشغيل الصحيح، ومطابقة `release.json.sourceSha` و
  `review.json.sourceSha` ونتيجة Actions لذلك commit.
- نجاح بناء Cloudflare وظهور إصدار Worker جديد فعال بنسبة 100% مرتبط بهذا البناء.
- مقارنة بايتات HTML وملفات JavaScript والعامل والبيانات المنشورة بعينات من الحزمة المراجعة،
  والتحقق من ترويسات الحماية وإعادة التحقق `ETag`/`304` ومسارات API المحمية. تستخدم أصول
  Cloudflare `public, max-age=0, must-revalidate`؛ ترويسات Pages تحت إدارة GitHub وتُسجل كما هي.
- تشغيل فحص النسخة المنشورة واختبار الإقلاع والواجهة العربية والإنجليزية وتنزيل Word.

تختبر فحوص PR ضغط الحزمة وفكها والتحقق من كل ملفاتها، ورفض المسارات الهاربة والروابط والبصمة
الخاطئة والمراجعة الفاشلة. تبقى دورة نشر الأرشيف العام وتنزيله من Cloudflare بحاجة إلى تحقق
بعد التفعيل؛ لا يمكن إثباتها من تشغيل PR الذي يمنع النشر.

## الرجوع عند الحاجة

إذا فشل البناء أو التحقق قبل الرفع، تبقى نسخة Cloudflare الحالية؛ تُراجع الأسباب قبل إعادة
المحاولة. إذا ظهر خلل بعد نشر Worker، يعاد تفعيل الإصدار
`ed931204-dd27-4c5a-8d22-4e03031ff927` بنسبة 100% من سجل نشر Worker، ثم تُفحص الخدمة.
يوقف النشر التلقائي مؤقتًا إذا كان سيعيد نشر الإصدار المعيب أثناء التشخيص، ويُوثق أي تغيير له.

للرجوع عن الدفعة في المصدر وPages، يُعد طلب دمج يعكس commit دمج الدفعة، وتُراجع فحوصه قبل
دمجه. قبل دمج هذا الرجوع الكامل تُعاد أوامر Cloudflare إلى `npm run build` و
`npx wrangler deploy` لأن المصدر السابق لا يحتوي على المستورد. يعيد مسار Pages السابق نشر
النسخة المرتجعة بعد الدمج. يجب فحص الاستضافتين بعد الرجوع، ثم توثيق الإصدار النشط والإعدادات.
